# اتصال اولیهٔ مجوزهای دستیار به RLS

این مرحله فقط دسترسی‌های خواندن مشخصی را فعال می‌کند؛ هیچ مجوز بررسی/تأیید، ویرایش یا حذف به دستیارها نمی‌دهد.

## مهاجرت
`supabase/migrations/20261016190000_wire_read_only_staff_permissions.sql`

- تابع قدیمی `public.is_admin()` را به شناسهٔ مدیر اصلی تنظیم‌شده متصل می‌کند تا نقش متنی `admin` به‌تنهایی دسترسی مدیریتی ندهد.
- مجوز `users.read` را برای خواندن پروفایل‌های کاربران، رانندگان و فرستندگان بار به کار می‌گیرد.
- مجوز `loads.read` را برای خواندن بارها، پیشنهادها، محموله‌ها و رویدادهای محموله به کار می‌گیرد.
- مجوز `verification.read` را برای خواندن پرونده‌ها، رویدادها و اسناد احراز هویت به کار می‌گیرد.
- دسترسی نوشتن یا تصمیم‌گیری در مورد احراز هویت را فعال نمی‌کند.

## نکات مهم پیش از اجرا
1. ابتدا تمام مهاجرت‌های قبلی این شاخه را بازبینی کنید و ترتیب اجرای آن‌ها را رعایت کنید.
2. شناسهٔ مدیر اصلی باید از مسیر مورد اعتماد تنظیم شده باشد؛ تا آن زمان، سیاست‌های مدیریتی عمداً بسته می‌مانند.
3. این مهاجرت روی پایگاه دادهٔ واقعی اجرا نشده است. ابتدا در محیط آزمایشی با حساب‌های کاربر عادی، دستیار بدون مجوز، دستیار دارای هر مجوز و مدیر اصلی آزمایش شود.
4. مجوز `users.read` امکان مشاهدهٔ فیلدهای جدول‌های پروفایل را می‌دهد؛ فقط به افرادی بدهید که واقعاً باید آن اطلاعات را ببینند.
5. دسترسی‌های `users.support`, `loads.manage`, `verification.review`, `reports.read`, `dashboard.read` و `activity.read` هنوز به عملیات مشخص متصل نشده‌اند.

## تست‌های لازم
- دستیار بدون مجوز نمی‌تواند همهٔ پروفایل‌ها، بارها یا اسناد احراز هویت را بخواند.
- دستیار دارای `loads.read` نمی‌تواند با این مجوز رکوردها را تغییر دهد.
- دستیار دارای `verification.read` می‌تواند اسناد احراز هویت را بخواند، اما نمی‌تواند پرونده را تأیید/رد یا تغییر دهد.
- کاربران عادی همچنان فقط بر اساس سیاست‌های مالکیت و مشارکت قبلی خود دسترسی دارند.
- مدیر اصلی می‌تواند دسترسی مدیریتی داشته باشد و هیچ حساب دیگری صرفاً به‌خاطر `role = 'admin'` آن را به دست نمی‌آورد.

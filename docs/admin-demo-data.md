# جداسازی داده‌های نمایشی پنل مدیریت

## هدف
داده‌های نمونه پنل مدیریت (کاربران، مدیران، رویدادها، تیکت‌ها، آمار و گزارش‌ها) از مسیر انتشار قابل کنترل باشند؛ خاموش‌کردن حالت نمایشی نباید نیازمند حذف دستی بخش‌های UI یا تغییر چندین فایل باشد.

## کلید کنترل واحد
- متغیر: `VITE_ENABLE_ADMIN_DEMO_DATA`
- توسعه محلی: اگر متغیر تنظیم نشده باشد، پیش‌نمایش در حالت `vite dev` فعال است.
- build آزمایشی: مقدار `true` را فقط در محیط آزمایشی قرار دهید.
- build انتشار: مقدار `false` را در محیط انتشار تنظیم کنید؛ اگر متغیر تعریف نشده باشد، حالت نمایشی در build تولیدی غیرفعال است.
- نمونه تنظیمات در `.env.example` قرار دارد. فایل‌های واقعی `.env.local` را وارد Git نکنید.

## رفتار هنگام غیرفعال بودن
ورود آزمایشی مدیران و داشبوردی که داده‌های ساختگی نمایش می‌دهد، به‌جای نشان‌دادن اعداد غیرواقعی، صفحه توضیحی غیرفعال بودن پیش‌نمایش را نمایش می‌دهند.

## رفتارهای تعاملی پیش‌نمایش
- در بخش تیکت‌ها، بازکردن پرونده و تغییر وضعیت بین «باز»، «در حال بررسی» و «بسته» قابل آزمایش است.
- این تغییرها فقط در state صفحه نگهداری می‌شوند و با refresh از بین می‌روند؛ این رفتار عمداً داده آزمایشی را از ذخیره‌سازی واقعی جدا نگه می‌دارد.
- گردش‌کار پاسخ‌دهی، تخصیص مسئول و ذخیره دائمی تا زمان طراحی API و کنترل دسترسی سمت سرور فعال نیست.

## نکات امنیتی مهم
این کلید صرفاً یک کنترل UI/build است و جایگزین احراز هویت یا مجوزهای سمت سرور نیست. پیش از اتصال به اطلاعات واقعی باید:
1. ورود آزمایشی و رمزهای ثابت با احراز هویت واقعی جایگزین شوند.
2. نقش و مجوز هر عملیات در API/پایگاه داده بررسی شود؛ مخفی‌کردن منو کافی نیست.
3. داده‌های کاربران، بارها، مالی، تیکت‌ها و رویدادهای ممیزی از repository/API واقعی خوانده شوند.
4. ماژول داده‌های نمونه جدا از ورودی اصلی برنامه نگه داشته شود و فقط در حالت نمایشی بارگذاری شود.
5. برای هر عملیات حساس، رویداد ممیزی سمت سرور و آزمون دسترسی ثبت/اجرا شود.

## چک‌لیست انتشار
- [ ] `VITE_ENABLE_ADMIN_DEMO_DATA=false` در محیط انتشار تنظیم شده است.
- [ ] مسیر مدیریت دیگر ورود آزمایشی یا اعداد/تیکت‌های نمونه را نشان نمی‌دهد.
- [ ] آزمون build، typecheck و lint موفق است (برای این کار workflow بررسی پنل مدیریت اضافه شده است).
- [ ] پیش از فعال‌سازی پنل واقعی، احراز هویت و مجوزهای سمت سرور بازبینی شده‌اند.

## محدوده این تغییر
- رکوردهای ساختگی داشبورد و حساب‌های ورود آزمایشی در `src/features/admin/demoData.ts` متمرکز شده‌اند.
- ورود آزمایشی و کامپوننت داشبورد به‌صورت شرطی/پویا بارگذاری می‌شوند؛ با خاموش بودن پرچم، مسیر عادی برنامه آن‌ها را بارگذاری نمی‌کند.
- بسته‌ساز ممکن است chunk جداگانه پیش‌نمایش را در خروجی build تولید کند؛ این به معنی فعال یا قابل‌دسترسی بودن آن نیست. اگر الزام انتشار این است که حتی فایل chunk نمونه در artifact نباشد، باید build تولیدی جداگانه با حذف کامل ورودی نمایشی اجرا و artifact بررسی شود.
- داده‌های نمونه بارها و سایر بخش‌های کاربر در فایل‌های دیگر برنامه هنوز در این تغییر هدف قرار نگرفته‌اند؛ این PR فقط داده‌های پنل مدیریت را سامان‌دهی می‌کند.
- اتصال repository واقعی، حذف ورود آزمایشی از نسخه نهایی و آزمون مجوزهای سمت سرور همچنان مرحله بعدی است.
